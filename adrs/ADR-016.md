# ADR-016 — Python-first reusable AI component platform

**Status:** ACCEPTED — maintainer-directed architecture decision  
**Date:** 2026-09-22  
**Owner:** Project maintainer  
**Class / priority / reversibility:** A / P0 for this strategic increment / Type 2  
**Depends on:** Intent 1.0 + [IA-001](../intent-amendments/IA-001.md), existing
canonical documents, ADR-001, ADR-002 and retained governance ADRs.  
**Supersedes:** No prior ADR in full. Extends ADR-001's initial-runtime scope
to ongoing Python component delivery; preserves ADR-002 package boundaries.  
**Acceptance basis:** Maintainer's explicit Python-first amendment and first
milestone instruction, supported by the linked impact/alternatives review.
Acceptance is not execution evidence or approval of every later milestone.

## Context and decision

[Repository impact assessment](../planning/PYTHON-FIRST-IMPACT-ASSESSMENT.md)
establishes the current source baseline and exact intent tension. An ADR
cannot amend upstream authority: IA-001 separately records the maintainer's
intent amendment under intent §55. Canonical semantics remain technology-neutral.

Keep `legoai-reference` and its owner subpackages on the ADR-001 CPython
baseline. Maintain reusable Python capabilities as the principal delivery
units, adding separate distributions with distinct import roots only when
implemented consumer needs justify them, as already demonstrated by
`legoai-document`. Keep built-in Ollama in place; new provider/framework/protocol
dependencies belong in optional replaceable integration packages. No physical
relocation, namespace conversion, public registry publication or dependency
upgrade is part of this decision.

Use composition for Agents and preserve existing canonical Skill semantics.
Workflow definitions own process logic and supervised concurrency, while the
existing governed execution owners retain authority and effect accounting.
Team composition preserves Role/Actor distinctions and separation of duties.
Deterministic test/lint/typecheck/tool adapters are capabilities, not Agents.

ForgeAI is an application consumer of reusable engineering workflows and the
Software Engineering Team. Generic engineering behavior must remain independently
usable without ForgeAI. Extract for a first real consumer and harden with a
second; do not create a universal catalog of empty packages.

## Alternatives and burdens

| Option | Assessment |
|---|---|
| Continue describing Python solely as first reference substrate | Compatible but underspecifies the maintainer's ongoing reuse investment and allows avoidable mirrored implementations |
| Python-first components plus replaceable adapters (selected) | Fits existing code and boundaries; additive pack/install checks are the principal new cost |
| Mirror all components in several languages/frameworks | Multiplies implementation, security qualification, dependency and release work without a consumer; rejected |
| Rewrite on a vendor Agent framework | Loses qualified baseline and shifts semantic ownership to vendor abstractions; rejected |
| Split every logical owner into a distribution now | Adds version/release coordination without a demonstrated independent release requirement; rejected |

| Solo burden | Selected obligation |
|---|---|
| Implementation | Typed bounded capability APIs and explicit composition; preserve runtime rather than rebuild |
| Operations | Existing local scope; protocols/distribution require later operational qualification |
| Maintenance | One primary implementation per capability; review adapter drift separately |
| Testing | Independent packs, contracts, import boundaries, inert imports and clean installations |
| Local development | Existing uv/CPython toolchain; additional pack directory only for actual code |
| Deployment | Optional packages, no mandatory service/broker/sandbox technology introduced |
| Learning | Existing LegoAI semantics and ordinary Python, then each demanded integration boundary |

If real non-Python consumers cannot meet latency, deployment or regulatory
constraints through a protocol/adapter, assess a bounded native realization
with compatibility tests. This changes the evidence for that component, not
the default requirement to port the whole platform.

## First implementation and gates

Authorize the bounded M1 in the [forward plan](../planning/PYTHON-FIRST-REUSABLE-AI-PLATFORM-PLAN.md):
pure repository text inspection and its intake consumer in `legoai-engineering`.
It has no runtime dependency, host access or registered capability claim.
This is a concrete preparatory implementation, not a new semantic Kernel type.

Future live repository access requires governed acquisition and source/tenant
checks. Code execution requires explicit containment, termination, resource
and uncertain-effect behavior; ADR-012 remains Proposed. ADR-014 remains the
supported application-authoring gate and ADR-013 the production-observation
gate. Neither is silently accepted by this decision. ADR-015's structured
supervision does not supply Workflow semantics or sandbox isolation.

Security is enforced outside Agents. Reuse canonical Artifact references when
preserving results, authorized Evaluation when assessing behavior, and existing
Evidence custody for claims. A coordinate report or Agent score is none of these
by itself. Contracts, Plugin admission and conformance obligations are unchanged.

## Migration, review and stop

No API/data migration; no old ADR is erased. Index entries and forward pointers
identify this increment. Future package extraction must maintain existing import
compatibility or deliberately version the break. No framework/protocol provider
support is implied without an implementation consumer and qualified boundary.

Static review: selected design preserves ADR-002 direction, existing optionality,
SPEC Skill/Agent/Workflow/Team meaning, and external governance. It avoids a
duplicate Skill/Artifact hierarchy and does not promote private runtime wiring.
Review performed by the implementing assistant; independent review is not claimed.
M1 local validation is complete; the forward plan records the user-supplied
results and successful formatter recheck. M2 remains unstarted and requires
separate milestone authorization.
