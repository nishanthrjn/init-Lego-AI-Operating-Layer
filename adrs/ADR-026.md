## Decision question

What minimum public composition mechanism lets Model and Generative Media reuse
execution controls without importing private Core code, while each retains its
operation, result, disclosure and effect semantics? This does not decide Secret
material handling, provider protocols, remote VTO or arbitrary workflow execution.

## Decision drivers

Mandatory: preserve owners, current authority, exact contribution/configuration,
one-shot claim, truthful effects and dependency direction. Rank other tradeoffs:
small public surface, one authority for control rules, bounded local lifetime,
then migration ease. REUSE > EXTEND > CREATE.

Model and media are the two real invoking planes sharing context, selected
contribution, coordinate, claim once and canonical settlement. ForgeAI and
DocuMind consume the Model host; they are not independent evidence for a universal
operation host. Select Option A. `open_governed_execution` is a candidate name,
not an architectural requirement. One reference realization does not justify
adding a new Protocol merely to provide a public facade.

## Considered alternatives

### Option A — Bound public execution composition facade

Benefits: existing controls behind one coherent public seam. Costs: explicit
authority inputs and lifecycle contract. Risks: an overbroad factory becoming an
implicit grant issuer or service locator. Conformance: trusted bootstrap remains
distinct from invoking-owner data and business effects.

Solo burdens: implementation wraps existing controls; operations stay local;
maintenance adds a small versioned surface; testing needs two consumer plus
forgery/race fixtures; local development needs no provider; deployment adds no
service; learning is limited to the bound lifecycle.

| Responsibility | Accepted contract |
| --- | --- |
| Trusted bootstrap | Validate independently established operator Principal/tenant/policy/grant basis, exact configuration and selected admitted contribution. No provider I/O, Secret resolution, arbitrary loading or effectful initialization at open |
| Contribution binding | Internalize catalog/lifecycle/resolution wiring. Freeze exact offer/version/binding/configuration. A declaration is not trust evidence or authority |
| Establish context | Issue canonical context and correlated operation identity for allowed scope. No caller registry mutation or tenant/subject switching |
| Coordinate | Canonical coordination result under current applicable controls, bounded preparation and explicit failures |
| Claim once | Atomically claim one invocation attempt under this facade/execution. Duplicate, foreign, stale or currently unauthorized scope refuses before owner invocation. Retain the claim guard through settlement |
| Settle | Verify owner lineage, execution identity and legal state transition for canonical state/error/effect facts. Do not infer business success or convert unknown to none because a receipt is absent |
| Close | Stop new contexts/claims; cancel supervised work and wait only within a configured finite shutdown bound. Preserve unresolved effects/custody duties and truthful cessation |

Semantic owner: Runtime integrates Execution, Governance, Lifecycle and Evidence
without taking their semantics. Allowed consumers: trusted Model/media composition.
Implementation: private reference controls initially. Substitution requirement:
Core may replace those controls without changing consumer requests/results or
requiring private imports. No hypothetical second host backend is invented.

Use existing canonical `ConfigurationRevisionRef`, `CapabilityOffer`/`CatalogEntry`,
`ExecutionContext`, `CoordinationRequest`/`CoordinationResult`, `ExecutionResult`,
`EffectExtent` and errors. Caller-created `SecurityContext` is not a grant mechanism.
The first realization is single-operator, explicit-tenant, trusted-process and
thread/event-loop confined. Capacity, request deadlines, preparation and shutdown
bounds must be finite and documented before implementation. Exhaustion refuses
instead of evicting claim guards; restart restores no authority. Release technical
state only after retaining or reporting unresolved obligations.

Invocation stays outside this facade. No arbitrary callback, result union or
provider dispatcher. Model owns response meaning; media owns uploads, image
disclosure, workflows, jobs, reconciliation, retrieval and retention; documents
remain document-owned. Provider adapters own wire serialization. No detached
worker, workflow engine, background session renewal or global singleton.

### Option B — Extend Model host into a universal capability host

Benefits: one apparent entry point. Costs: heterogeneous configurations/results
and job lifetimes. Risks: flattening disclosure/job truth. Conformance: no
whole-operation substitutability evidence exists.

Solo burdens: implementation adds generic dispatch; operations add modes;
maintenance couples owners; testing multiplies operation combinations; local
development imports unrelated capabilities; deployment complicates optionality;
learning requires a framework. Reject `UniversalCapabilityHost`,
`GenericOperationPort`, `AnyResult`, `CallbackExecutionPort` and plugin sessions.

### Option C — Public raw primitives with consumer-reconstructed hosts

Benefits: flexible, close to current wiring. Costs: duplicated integration.
Risks: registry authority leaks/private shapes frozen publicly. Conformance:
type substitution alone does not remove duplicated enforcement ownership.

Solo burdens: small initial implementation; operations/debugging span host
variants; maintenance duplicates rules; testing repeats qualification; local
development wires registries; deployment configures low-level participants;
learning requires Core internals. Reject public raw registries/service locators.

### Do nothing / defer

Benefits: no immediate migration risk. Costs: M-01 persists. Risks: Core changes
break consumers; H-01 remains separately open. Conformance: no new support claim.
Solo burdens: no implementation; operations unchanged; maintenance coupled;
testing retains debt exceptions; local development unchanged; deployment gains
nothing; learning requires private knowledge. Valid temporary state, not closure.

### Design-principle comparison

| Principle | A: bound facade | B: universal host | C: raw primitives | Defer |
| --- | --- | --- | --- | --- |
| SRP | Controls only | Mixes domains | Splits control authority | Existing mixing |
| OCP | Providers evolve independently | New result kinds change host | Control changes affect consumers | Private changes break apps |
| LSP | Same coordination contract | No whole-operation equivalence | Hosts can diverge | Existing risk |
| ISP | Narrow invoking controls | Unrelated operations | Excess machinery | Excess private imports |
| DIP | Public contracts | Broad abstraction hides coupling | Concrete registry exposure | Boundary debt |
| DRY | One control authority | Shares unlike meanings | Repeats control wiring | Duplication retained |
| KISS | Small seam | Larger than need | Simple locally, complex overall | Simple now, debt later |
| YAGNI | Two matching consumers | Speculative framework | Excess mutation APIs | No abstraction or solution |
| SoC | Bootstrap separate from effects | Blurs owners | Consumers mix concerns | Mixing retained |
| Law of Demeter | Bound facade and immutable values | Growing object graph | Registry traversal | Private graph traversal |

## Decision

ACCEPT_ADR_026

Accept Option A: only the narrow public runtime composition boundary for shared
governed execution controls of the Model and Generative Media invoking planes.
ADR-014 section 15 records the additive public-boundary extension. Acceptance
does not authorize implementation, credential support, image/provider disclosure,
live media, public provider access, remote VTO, generic workflow hosting or
generic capability dispatch. ADR-027 and MPBP-1 are not accepted.

## Consequences

### Positive

Media can use supported Core controls while preserving owner-specific results.

### Negative

A versioned facade needs lifecycle/error/capacity contracts and migration tests.
Moving bootstrap may expose hidden assumptions in existing consumers.

### Risks accepted

Accepted architecture scope is trusted, single-operator local composition;
it claims neither hostile-plugin isolation nor multi-tenant IAM. Architecture /
Execution owners retain responsibility for those limits and implementation review.
The facade verifies lineage/transitions, not the truth of a compromised trusted
owner's business assertions. No runtime enforcement, timing or provider guarantee
is qualified by this acceptance. Revisit for a real consumer requiring different
coordination or durable recovery, not hypothetical scale.

## Security impact

Authority comes from trusted operator composition/current controls, never plugin
selection, configuration, Approval alone or model output. Forged contexts and
duplicate claims fail. Actual external handoff/Secret consumption still needs
its own final gate; coordinate/claim does not authorize every later request.

Settlement verifies provenance/transitions and relies on admitted owner evidence;
it cannot prove a malicious trusted owner reports truth. Untrusted outputs cannot
directly settle. Cancellation/timeout do not rewrite earlier effects. Unknown
remains unknown. Mandatory unavailable controls block new protected work.

Private remain private: `ExecutionCoordinator`, `StaticSecurityContextRegistry`,
reference registries, `reference.resolution.resolve`, lifecycle functions,
`runtime._composition` and ordering domains. No public raw Secret/material
callback approved. No universal generic capability host approved.

## Resource impact

No new dependency, server or global registry. Finite capacities/deadlines and
bounded close do not replace Resource-owner accounting or evidence duties.
No automatic retry, fallback or detached reconciliation worker.

## Conformance impact

Future checks: valid/forged context controls; exact tenant/configuration/contribution;
revocation after preparation; concurrent duplicate claims; cancellation/timeout
before/after effects; failed settlement retaining unknown; capacity exhaustion;
bounded close; inert construction; both consumers; allowed/forbidden imports.
Preserve independent domain fixtures. The document validator proves only local
structure/scope, not acceptance or runtime security.

### Design principles and solo burden review

SRP and SoC hold because Core controls and owner operations remain distinct.
OCP and LSP require substitutable providers to preserve their owner effect/failure
contracts, not a generic result shape. ISP and DIP hold with a small public seam
and no internal types. DRY removes repeated control integration; KISS/YAGNI prefer
the proven two-consumer seam over universal hosting. Law of Demeter is satisfied
without reaching through registries; immutable canonical value traversal is valid.

All seven burdens remain preferable to B/C: bounded wrapper implementation;
local operations; one maintained compatibility surface; focused two-consumer and
failure-boundary tests; provider-free local development; no extra deployment
service; one small lifecycle to learn. Defer is cheaper only by leaving M-01
unresolved. No materially simpler conforming option closes that gap without
duplicating controls or freezing private internals. Generic scale is not a driver.

Public contract sufficiency: owner, consumers, binding, context provenance,
coordinate/claim/settlement, failure/effects, finite lifecycle and private boundary
are established. Class/method names and exact capacity/data structures need not
be fixed at architecture acceptance. Implementation must demonstrate cancellation
of supervised work through owner cooperation; close cannot dispatch operations,
invent a callback executor or falsely report remote cessation.

Residual limitations: trusted local scope; no implementation proof; currentness,
capacity, cancellation and evidence behavior require future contract tests;
ADR-027 remains Proposed with its blocked security/amendment scope. ADR-020's
remote-image prohibition remains. MPBP-1, raw env credentials, media probes and
personal-image transfer gain no authority. Neither ADR-027 nor accepted Secret
rules were changed by this review.
