# ADR-023 — Remote Bearer Credential Profile for Single-Operator Model Providers

**Status:** ACCEPTED — 2026-10-09, by explicit maintainer decision, for the
bounded SRCP-1 scope in §12. History: drafted and proposed 2026-10-09 after
OPENAI-COMPATIBLE-REMOTE-CREDENTIAL-1 was stopped for conflicting with
ADR-007, ADR-010 and ADR-014; accepted the same day with one editorial
clarification to Option C (§6). Acceptance applies the addenda drafted in §13
(ADR-010 §23, ADR-007 §18, ADR-014 §14.18). It authorizes **no
implementation**: not the credential source, the T2 transport, the attempt
store, any settings field, any remote provider or KISSKI call, or ForgeAI or
ComfyUI remote execution. Runtime behavior is unchanged: REMOTE is still
refused at open. The next gate is REMOTE-MODEL-DISCLOSURE-1
([ADR-024](ADR-024.md), accepted 2026-10-09; not yet implemented).

**Date:** 2026-10-09

**Decision class:** C — required before any credential-bearing Model provider path

**Reversibility:** Type 2. The profile is additive and scoped. The stronger
ADR-007/010 profile stays normative wherever its assumptions hold.

**Depends on:** ADR-005, ADR-007, ADR-008, ADR-009, ADR-010, ADR-014 §14.

**Relates to:** SECRET-REF-1A and SECRET-USE-DURABLE-CUSTODY-1 (locally
qualified), SECRET-REF-1B (deferred), REMOTE-MODEL-DISCLOSURE-1 (SEC-039, not
yet decided), and the decision records
[consumer boundary](../planning/LEGOAI-SECRET-REF-1B-CONSUMER-BOUNDARY-DECISION.md)
and [source + transport](../planning/LEGOAI-SECRET-REF-1B-SOURCE-TRANSPORT-DECISION.md).

## 1. Context

LegoAI's OpenAI-compatible Model adapter (`legoai.reference.model_openai_compatible`)
is locally qualified for **credential-free `ModelDeployment.LOCAL`** use only.
`REMOTE` is refused at open (ADR-014 §14.5). The adapter's `_post` calls
blocking `urllib` through `asyncio.to_thread`. It sends no `Authorization`
header, and settings carry no credential field.

The Secret mechanism (ADR-010) is realized only for Stage A: one synthetic
exact use, ordered under a shared `_OrderingDomain`, with a durable source
ledger and separate Evidence custody. `_SecretState` generates synthetic
random bytes. There is **no real credential source** and **no credential-
bearing transport**. On 2026-10-07 SECRET-REF-1B was deferred by the
maintainer: "BLOCKED ON QUALIFIED CREDENTIAL TRANSPORT". No further work was
to start without a concrete credentialed consumer and explicit authorization.

### 1.1 Trigger and first intended consumer

The concrete consumer now exists. ForgeAI's Coding Agent and Independent
Reviewer need a remote, OpenAI-compatible model endpoint that authenticates
with a Bearer API key. The first intended endpoint is the KISSKI (GWDG)
service. KISSKI is the motivating consumer only. Nothing in this decision is
KISSKI-specific, and no KISSKI type, setting or branch is introduced
(ADR-014 §14.3).

### 1.2 Decision question

Can LegoAI support a remote Bearer-authenticated model provider on the
single-operator local host while preserving the authority, custody and
non-leakage guarantees of ADR-007/010? If not, exactly which guarantee needs a
deliberately narrower profile?

## 3. Exact conflict

A direct credentialed remote call, as requested by the
OPENAI-COMPATIBLE-REMOTE-CREDENTIAL-1 slice, conflicts with:

1. **ADR-014 §14.5.** REMOTE construction is refused until
   REMOTE-MODEL-DISCLOSURE-1 exists.
2. **ADR-014 §14.7 / ADR-010.** Credentialed providers are unsupported until
   ADR-010 is realized, and no credential source exists.
3. **ADR-010 §8.2 step 5, ADR-007 §8.** Time validity at actual acceptance
   needs a qualified check-to-acceptance bound or an equivalent atomic guard.
4. **ADR-010 §8.3.** A provider with independently effective revocation needs
   an equivalent-order proof. Otherwise that guarantee is unsupported.
5. **ADR-007 §6.2.** No durable credentialed external-attempt record exists.
   The Execution Coordinator's `_states`/`_claimed` are in-memory.

## 4. Three currentness problems, analyzed separately

Let P be preliminary authorization, R material realization (acquisition into
the protected scope), G the final gate check, H the first credential-bearing
bytes accepted by the local OS send primitive, and V provider receipt and
processing.

```text
P (preliminary auth) → R (realize material) → connect/TLS (no credential)
   → G (final check, inside domain) → H (OS accepts credential bytes)
   → V (provider receives / processes)
```

### 4.A Local authority currentness: strongly orderable

Operator revokes a grant, a Policy changes, a SecretRef mapping or revision
becomes ineligible, the binding is disabled, the operation is cancelled.

These are **events**. ADR-007 requires each participating invalidator to enter
the same arbitration domain before it becomes effective. If G and H both occur
inside one domain occupancy, M either happens before G (G refuses) or waits
until after H (H won and is recorded). No time bound is needed: mutual
exclusion is the guarantee.

What prevents this today is not a law of nature. It is two concrete facts:
- the current transport (`urllib` via `to_thread`) cannot place H inside the
  domain, because `urlopen` combines DNS, connect, TLS, send and response wait
  into one blocking call;
- the Stage-A domain profile admits no network operation under the domain.

A **nonblocking** credential-bearing `send` performs no wait: it either
accepts some bytes or reports would-block. Placed inside the domain, with
connection and TLS handshake completed beforehand without credentials, G→H is
one domain occupancy with no wait. That satisfies ADR-007 §6.2's ordering for
event invalidators.

Partial writes do not break this: each continuation write is its own gated
occupancy (§7.3). Would-block releases the domain and waits for readiness
**outside** it.

**Conclusion 4.A.** Local event currentness need not be weakened. It requires
an explicit admission that a nonblocking, credential-bearing socket write is a
bounded local acceptance step permitted under the domain. That is a scope
admission like Stage A's bounded SQLite commit, not a weakening.

### 4.B Locally declared material validity: split

- **Event-based facts** (selected revision, revision retirement, local
  disablement, mapping change) behave like 4.A: strongly orderable.
- **Wall-clock facts** (a locally asserted credential expiry, time-windowed
  grants, deadlines) are the exact unprovable property. The counterexample in
  the transport decision §5 stands: G samples time t < E, the thread is
  suspended, it resumes after E, and the OS accepts bytes at H > E. No
  competing domain mutation is involved, so mutual exclusion does not help.
  CPython on Windows supplies no joint "check time and send" primitive, and
  host suspension (sleep, VM pause, debugger) has no bound.

Turning expiry into an ordered event (a timer entering the domain at E) moves
the ordering into the domain. But it redefines validity as "before the expiry
event in domain order", not "before E in wall-clock time". The two differ by
domain occupancy plus timer lateness, and that difference is unbounded under
suspension. That is a semantic change and must be named, not hidden.

**Conclusion 4.B.** Event-based validity: retained. Wall-clock validity at H:
**cannot be proven** on this platform. A profile may only claim domain-ordered
expiry plus a check-time margin and after-the-fact detection (§7.4).

### 4.C Remote provider currentness: outside any local guarantee

The provider revokes or expires the key, disables the account, or changes
state between G and V. ADR-010 §8.3 already states that a local lock cannot
order this, and that such a provider is "unsupported for the affected
guarantee/path". No local mechanism can supply the equivalent order. That
would need a provider protocol (lease, nonce, version precondition), and a
plain Bearer API key offers none.

What the missing guarantee would protect against needs to be precise.
- The credential travels only to the **admitted recipient**: the configured
  HTTPS origin that is bound in the Secret mapping as the credential's issuer
  and audience. No redirects, no proxies, no other origin.
- If the issuer revoked the key remotely, the disclosed bytes go to the party
  that issued and revoked them. **No new party learns the credential.** The
  observable consequence is a provider rejection (401/403), which is useful
  failure behavior.
- What is lost is the claim that "no use of a remotely invalid credential was
  attempted". Not lost: the confidentiality of the credential against third
  parties, which TLS peer verification and the recipient binding protect.

**Conclusion 4.C.** The profile claims **no** remote currentness. It is
admissible only when the credential's recipient is its issuer or the issuer's
designated service, as bound in the mapping. That requirement is what makes
the gap bounded rather than a disclosure risk.

### 4.D Does the previous impossibility claim still hold?

**Partly.** It holds exactly for wall-clock validity at H (4.B) and for remote
currentness (4.C, already conceded by ADR-010 §8.3). It does **not** hold for
local event invalidation (4.A) or event-based material validity. Those become
achievable once a nonblocking credential-bearing write is admitted under the
domain. The 2026-10-07 record was correct that no **current** transport
achieves this, and that T2 has not been built. Its statement that "no
transport profile yet satisfies ADR-010" remains true for the unmodified
wall-clock requirement.

## 5. Invariants that MUST remain

1. No raw credential in `ModelBindingConfig`, any provider settings,
   `LocalHostConfig`, `ChatRequest`/`EmbeddingRequest`, results, Agent prompts
   or any application (ForgeAI) value. Settings carry a `SecretRef` only.
2. No ambient credential source: no environment lookup, `.env`, SDK default
   credential, keyring discovery or fallback, in the adapter or in ForgeAI.
3. Purpose binding: the use declaration binds requester, tenant, binding
   identity, provider target (origin and API root), consumer and version,
   action (chat or embeddings) and SecretRef revision. A reference admitted
   for a different purpose, binding or target is refused.
4. Every local event invalidator participates in the domain and is strictly
   ordered against H (4.A).
5. One attempt per invocation: no automatic retry, resend, provider fallback
   or credential fallback (ADR-008, ADR-010 §15).
6. A durable attempt record is committed before H (§8). Unknown never
   collapses to none.
7. No material, header, handle or material-derived fingerprint in any log,
   repr, exception, observation, Evidence, report or persisted record.
8. No credential cache across invocations. Material lives only for one
   admitted use.
9. ADR-014 REMOTE classification and REMOTE-MODEL-DISCLOSURE-1 remain
   independent and mandatory (§9).

## 6. Options

### Option A — Direct LegoAI credential profile (modified: SCOPED REMOTE CREDENTIAL PROFILE)

LegoAI owns the SecretRef, the operator-provisioned source, a private T2
transport and the attempt record. It realizes the Bearer material at the
protected use and sends it directly to the remote OpenAI-compatible endpoint.
It narrows exactly one ADR-007/010 property (wall-clock validity at H) and
claims nothing about remote currentness, as ADR-010 §8.3 already concedes.

### Option B — Full ADR-010 guarantee, unmodified

Build S1 + T2 + the attempt store, and also prove a check-to-acceptance time
bound. **This is not realizable on the reference platform** (Windows, CPython
3.14): no primitive jointly evaluates authoritative time and performs the
send, and suspension is unbounded (4.B). An unmodified Option B also cannot
admit any provider with independent revocation (4.C). Option B is therefore
not a viable path to a remote Bearer provider. It is listed only to show that
all of its realizable parts are already contained in Option A.

### Option C — External operator-owned credential broker / proxy

LegoAI talks credential-free to a local endpoint. An operator-run broker adds
the Bearer header and forwards to the remote provider. Processing remains
REMOTE (ADR-014 §14.5), so REMOTE-MODEL-DISCLOSURE-1 is still mandatory.

## 7. Recommendation: Option A as the SCOPED REMOTE CREDENTIAL PROFILE (SRCP-1)

Option A ranks first on criteria 1 (it preserves every invariant that is
realizable at all), 2 (it enables the consumer), 4 (reuse) and 5–6 (an
explicit, honest residual list). Option C ranks first only on speed for one
component. It fails criteria 1, 5 and 6: either it creates an ambient local
credential capability, or, if the broker authenticates its clients, it adds a
second, unqualified trust boundary outside LegoAI's attribution.

### 7.1 Guaranteed (retained)

1. Current local authority (grant, Policy, Approval where configured,
   binding/catalog suitability, operation cancellation) is checked at G,
   inside the domain. A local revocation that becomes effective before H
   prevents H. One that loses the order sees H recorded as accepted.
2. The current SecretRef mapping and revision eligibility are checked at G
   under the same ordering. A retired, replaced, disabled or wrong-purpose
   revision cannot start a protected send after its change is effective.
3. Purpose binding (§5.3) and recipient binding: material only to the
   mapping's admitted HTTPS origin, after TLS certificate and hostname
   verification, with no redirects, proxies or alternate targets.
4. Each continuation write of credential-bearing ciphertext is separately
   gated. Invalidation or cancellation that wins stops further writes and
   drops unsent buffers.
5. Exactly one attempt per invocation. No retry, no fallback, no credential
   caching.
6. A durable attempt record exists before H. Send and response observations
   are recorded as available. Crash recovery never resends (§8).
7. Containment: the material is absent, by construction, from settings,
   requests, results, Evidence, logs, repr, exceptions and their causal
   chains, and persisted records. Provider error bodies are never retained.
8. Explicit operator provisioning and admission. Explicit provider, binding
   and model identity in every attempt record.
9. Existing timeout, cancellation and effect semantics: NONE, UNKNOWN and
   COMPLETED stay distinct. A rejection after H is still a Model rejection,
   never a "Secret not used".

### 7.2 Intentionally NOT claimed

1. **Wall-clock validity at H.** Time-bounded facts (credential expiry known
   locally, time-windowed grants, deadlines) are enforced by (a) refusing at
   G unless at least a configured margin of validity remains, (b) a
   domain-ordered expiry event, and (c) a clock sample after H that records a
   time-validity violation observation if H occurred after E. A use that
   began validly but whose bytes left after E is **detected, not
   prevented**. No hard real-time claim is made.
2. **Ordering with independently changing remote provider state**:
   provider-side revocation, expiry or account disablement between G and V
   (ADR-010 §8.3 already concedes this).
3. **Recall of bytes after H.** Once the OS has accepted credential-bearing
   bytes, later invalidation stops only future writes (ADR-010 §10).
4. **Memory security** beyond ADR-010 §9: no zeroization, swap or dump
   protection, or protection from hostile in-process code.
5. **Provider behavior**: retention, training use or logging of the key or
   payload by the provider. That is REMOTE-MODEL-DISCLOSURE-1's subject, plus
   operator due diligence.

### 7.3 Transport requirements (private; no new dependency)

- One connection per attempt: no pool, no keep-alive reuse, HTTP/1.1, no
  redirects, no proxy (ambient or configured), no `SSLKEYLOGFILE` key logging,
  certificate and hostname verification required, no client certificate, no
  session resumption or early data.
- DNS, TCP connect and TLS handshake complete **before** realization or with
  no credential bytes, outside the domain.
- The request is serialized privately. Credential-bearing bytes are encrypted
  into a memory BIO (`ssl.SSLObject`) and handed to the OS only via
  nonblocking `send` inside the domain, each occupancy preceded by G.
  Would-block releases the domain and waits for readiness outside it.
- The response wait happens outside the domain. Response parsing reuses the
  existing adapter's qualified wire contract and error mapping (ADR-014
  §14.8).
- Send-progress observations are none, partial, all or unknown, never byte
  offsets.
- HTTPS is mandatory for credentialed bindings. `http` refuses at open.
  Loopback synthetic test servers use TLS with a test-only trust anchor;
  production HTTPS enforcement is never relaxed for tests.

### 7.4 Time-validity residual, stated as a number the operator controls

The margin is an explicit configured value, qualified at implementation.
This ADR invents no measured values. The guarantee is: "H is domain-ordered
before every local event invalidation and before the expiry event. At G at
least the margin remained. A violation of wall-clock expiry at H is recorded."
Credentials with **no locally asserted expiry** (typical static API keys)
leave grant windows and deadlines as the only time facts.

## 8. Credential source: S1, operator-provisioned immutable source

- **Owner:** a private reference realization behind Secret Access
  (`legoai.reference`), composed only by the runtime. It is not a Model
  adapter, ForgeAI or application concern.
- **Provisioning (bootstrap)** is a separate, explicit operator act before or
  at host open, distinct from the protected use:
  1. **Interactive secure input** (no echo), read **by the LegoAI source
     realization itself**. The application calls a runtime operation that
     returns only a `SecretRef`. ForgeAI never sees the bytes. Recommended
     first.
  2. **OS-protected credential store**, as a later, separately qualified
     bootstrap input. A keyring API name supplies no currentness proof
     (transport decision S3).
  3. **Explicit bootstrap injection** from an ordinary environment variable:
     **not authorized** (the consumer-boundary decision). Any future
     constrained process-injection source needs its own decision.
- **Exactness:** each provisioning creates a new owner-issued revision
  identity (never a digest of the material) bound to the owner/tenant, purpose,
  consumer, binding and the admitted recipient origin. Immutable bytes. No
  in-place replacement, alias, "latest", read or export API. Rotation means
  provisioning a new revision; the old one is retired under the domain.
- **Lifetime:** one process incarnation. No persistence of material. After a
  restart, the operator provisions again, under a new revision identity.
  Closing the source under the domain prevents further realization.
- **Use:** per invocation, realization into a protected scope after P, then G
  and H, then disposal on every exit path.

## 9. Durable attempt record: minimum custody

**Owner:** the existing Model invoking plane (governed Model call
composition), as selected in the transport decision §8. It is not Secret
Access, Evidence or the HTTP adapter. It is a narrow owner-local SQLite store,
not a workflow engine.

**Committed before H** (state `INTENDED`):
- attempt id, execution/operation id;
- principal and tenant;
- binding id, provider id, protocol (`openai-compatible`), deployment
  (`REMOTE`), endpoint origin and API root, model id;
- action (`chat` or `embeddings`);
- SecretRef identity, revision and mapping revision, plus the REMOTE
  disclosure admission reference;
- created-at and deadline.

**Never stored:** material, the `Authorization` header, a material-derived
fingerprint, TLS state, and request or response bodies. Prompt and code
custody, if any, is decided by REMOTE-MODEL-DISCLOSURE-1, not here.

**Appended observations:**
- `REFUSED_AT_GATE` (safe category);
- `CANCELLED_BEFORE_SEND`;
- `SENT_NONE` (proven zero credential bytes), `SENT_PARTIAL`, `SENT_ALL`,
  `SENT_UNKNOWN`;
- `RESPONSE_COMPLETE` (status class), `RESPONSE_INCOMPLETE`;
- `TIME_VALIDITY_VIOLATION`.

**Terminal categories:** `NOT_SENT`, `PROVIDER_REJECTED`, `COMPLETED`,
`UNKNOWN`.

**Recovery:**
- An `INTENDED` record with no send observation becomes `UNKNOWN`. Zero is
  never inferred from a missing record.
- One unresolved attempt blocks a second dispatch for the same operation.
- Recovery inspects and repairs only. It never reconnects, resends,
  re-realizes or restores authority.

Secret-use attribution (ADR-010 §14) is recorded by Secret Access against the
attempt id. Evidence custody stays separate (ADR-009).

## 10. Relationship to REMOTE-MODEL-DISCLOSURE-1

ADR-023 decides **credential handling**. It does not decide what may be sent.
- REMOTE classification, the tunnel rule and fail-closed disclosure stay
  exactly as in ADR-014 §14.5–14.6.
- A credential does not make a binding admissible, and admissibility does not
  provision a credential. Both checks run at **every invocation**.
- No repository, task or prompt content is sent remotely until
  REMOTE-MODEL-DISCLOSURE-1 is accepted and implemented. Even a synthetic
  compatibility probe needs a disclosure admission class for synthetic
  content.

**Sequence:**
1. ADR-023 accepted.
2. REMOTE-MODEL-DISCLOSURE-1 decided: [ADR-024](ADR-024.md), accepted
   2026-10-09.
3. Credential source, transport and attempt record implemented. These are
   testable against synthetic servers with no REMOTE settings enabled.
4. REMOTE settings enabled behind both gates.
5. Synthetic credentialed transport qualification.
6. One non-sensitive compatibility call: model list and one bounded chat
   under a synthetic-content disclosure admission.
7. ForgeAI remote-provider pilot.

Step 3 may start before step 2 completes. Step 4 may not.

## 11. Reuse by a future remote ComfyUI adapter

**Yes, for the credential primitive only.** The private
"purpose-bound Bearer HTTPS request" bridge, the S1 source and the attempt
record are protocol-agnostic. A remote ComfyUI adapter could reuse them for
its request/response calls. It keeps its own semantic Port, purpose, binding
and disclosure policy, and its own attempt actions. Not covered:
- WebSocket or streaming progress channels;
- large uploads or downloads;
- long-running job sessions.

Those need their own qualification. No ComfyUI design is made here.

## 12. Scope and non-goals

**Scope:**
- a single operator on a trusted local host;
- an explicitly configured provider using the OpenAI-compatible protocol;
- an explicit HTTPS endpoint;
- Bearer authentication only;
- chat (and embeddings under the same binding);
- one request attempt per invocation;
- interactive, attended use.

**Non-goals:**
- multi-tenant, hosted or SaaS use;
- unattended or background long-running credential use;
- automatic retry, fallback provider or credential fallback;
- caching, sessions or pools;
- OAuth, token exchange, refresh tokens, client certificates or arbitrary
  headers;
- structured output for this adapter (ADR-022 is separate);
- REMOTE Ollama;
- the disclosure decision itself;
- ComfyUI;
- any KISSKI-specific type.

This profile **does not** become the hosted or production profile. Hosted or
multi-tenant use requires a stronger, separate decision.

> **§23 Addendum — Scoped Remote Credential Profile (ADR-023).** For a
> single-operator trusted local host, a remote Bearer-authenticated model
> provider may be admitted under ADR-023's SRCP-1. Within SRCP-1:
> (a) §8.2 steps 1–4 and 6 apply unchanged. Every participating local

> **§18 Addendum — admitted nonblocking credential handoff (ADR-023).** Under

## 14. Consequences

**Positive:**
- A provider-neutral path to remote OpenAI-compatible providers.
- Local authority stays strictly ordered.
- Credential use is governed and attributable.
- No new dependency.
- A reusable private primitive.

**Negative:**
- A private HTTPS/1.1 client to own and qualify.
- A new owner-local store.
- An interactive provisioning step on every process start.
- A named residual (§7.2) that operators must understand.

**Neutral:** ModelPort, AgentRuntimePort, `ChatRequest` and the Model effect
vocabulary are unchanged. The credential-free LOCAL path is unchanged.

## 15. Implementation gates (each needs explicit authorization)

1. ADR-023 accepted. **Done 2026-10-09.**
2. Addenda 13.1–13.3 applied. **Done 2026-10-09.**
3. REMOTE-MODEL-DISCLOSURE-1 decided before REMOTE settings are enabled.
   Decided: [ADR-024](ADR-024.md) accepted 2026-10-09; not yet implemented.
4. All local invalidators relevant to the use participate in one ordering
   domain in the host composition. If not, the profile is unsupported for
   that composition.
5. Separate slices for:
   - the S1 source with interactive provisioning;
   - the T2 transport;
   - the attempt store;
   - the settings field and composition;
   - ForgeAI binding selection, with no credential handling in ForgeAI.

## 16. Qualification gates (offline; synthetic servers and canaries only)

- **Source:** duplicate revision, immutability, rotation and retirement,
  teardown, stale, wrong-purpose and wrong-target refusal, restart without
  restoring material, no environment or ambient read.
- **Ordering:** deterministic barriers before realization, before G, between
  G and H, and between partial writes. Each relevant invalidator wins or loses
  correctly. Cancellation at every point (transport decision §7).
- **Time:** margin refusal, the expiry event, an injected clock jump after G
  producing a recorded violation, no wall-clock validity claim in any output.
- **Transport:**
  - full, partial, would-block and unknown progress;
  - TLS want-read and want-write cases;
  - certificate or hostname failure before any credential bytes;
  - no redirect, proxy or key-log behavior;
  - one connection per attempt.
- **Wire:**
  - exactly one `Authorization: Bearer` header when a credential is
    configured, none otherwise;
  - the versioned API root preserved, `stream=false`, the exact model id;
  - HTTP 401, 403, 404, 429 and 5xx, timeout, reset, truncation and malformed
    bodies mapped as in ADR-014 §14.8;
  - no retry.
- **Durability:** a crash before the commit, after the commit and before H,
  after H and before the observation, and after the observation. Recovery
  never resends; a missing observation means UNKNOWN.
- **Containment:**
  - a canary absent from repr and str of every value;
  - absent from exceptions and their causes, logs, observations, Evidence and
    databases;
  - absent from echoed provider error bodies;
  - absent from test failure output.
- **Compatibility:** credential-free LOCAL OpenAI-compatible and Ollama
  regressions unchanged; REMOTE without disclosure admission refused before
  any request.

## 17. Rejected alternatives

- A plaintext `api_key: str` anywhere: ADR-010 §4A.
- Ordinary environment variable as a source: consumer-boundary decision §2.
- Resolve at startup and cache: ADR-010 §4B.
- Keep `urllib` and check before `_post`: G and H are separated by DNS,
  connect and scheduling waits, so even local event ordering is lost (4.A).
- A new HTTP library dependency: convenience is not ordering
  (transport decision T3).
- A blanket ADR-010/007 relaxation: unnecessary, because only one property
  needs narrowing and only inside a named profile.
- Option C as the architecture: an ambient local credential capability unless
  separately protected, and in either case credential use that LegoAI cannot
  attribute natively. It remains an operator's private choice outside
  LegoAI's claims, but it removes no LegoAI gate.

## 18. Revisit triggers

Any of the following needs a stronger, separate decision:
- more than one operator, any tenant sharing, or hosted use;
- unattended or background use;
- a provider offering a lease, nonce or version precondition that could
  supply remote equivalent order;
- a platform primitive that supplies a demonstrable check-to-send time bound
  (would allow returning to unmodified ADR-007 §8);
- a need for pools, sessions, streaming or token exchange;
- any observed canary leak or ordering failure.

## 19. Decision

Requested at proposal: **ACCEPT** ADR-023 as written (SRCP-1, Option A
modified), authorizing only the application of addenda 13.1–13.3 and the
REMOTE-MODEL-DISCLOSURE-1 decision as the next artifact; **or REJECT** it,
keeping remote Bearer providers unsupported.

**Recorded 2026-10-09: ACCEPTED** by explicit maintainer decision, for the
bounded SRCP-1 scope. Not authorized by acceptance:
- the credential source, the T2 transport or the attempt store;
- any remote provider or KISSKI call;
- ForgeAI or ComfyUI remote execution.

Remote Bearer providers remain **unsupported in the runtime** until the §15
implementation gates and §16 qualification gates are met.
