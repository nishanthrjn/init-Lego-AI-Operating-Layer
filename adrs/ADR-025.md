# ADR-025 — Bounded provider qualification and safe Model failure facts

Status: Implemented for review, 2026-10-10 (FORGEAI-FREE-GPU-MODEL-PROVIDER-1).
No live provider or repository disclosure is authorized by this decision.

## Requirements and contract sufficiency

Reuse ModelPort, ChatRequest/ChatResult, OpenAICompatibleSettings, governed
execution, ADR-023 Secret custody, ADR-024 disclosure, and the read-only
RepositoryWorkspacePort. ForgeAI has no infrastructure-provider domain types.

Two requirements could not be represented by the existing public composition:
the adapter did not expose a deterministic sampling setting, and governed
results collapsed transport/protocol/rejection facts into DependencyFailure.
Parsing exception text or reading private attempt custody from ForgeAI would
violate the public-boundary requirement. The implementation justification was
provided before these additions.

## Decision

* OpenAICompatibleSettings gains `deterministic: bool = False`. True adds only
  `temperature: 0` to the existing non-streaming request. Defaults retain the
  existing wire shape. This requests deterministic sampling; it does not promise
  reproducible provider implementation or model quality.
* Model values gain the closed ModelFailure vocabulary. Existing Model exceptions
  carry an optional typed failure, defaulting to provider_execution_failure.
  GovernedChatResult gains optional `failure`, absent on success. ModelPort,
  ChatRequest, ChatResult, Agent contracts and execution effect semantics remain
  unchanged. Diagnostics are invocation-local, contain no provider text, and are
  not authority, retry permission or a new custody record.
* Transport facts distinguish unavailable connection, timeout and protocol errors
  when observed. A bounded, strictly parsed error object may project only the
  exact codes `model_not_found` or `model_not_available`. HTTP 404 alone remains
  request_rejected. Missing facts remain provider_execution_failure. The one
  adapter parser serves both local and remote calls.
* Local response reads stop at 1 MiB plus one sentinel byte. Exceeding the bound
  leaves the effect uncertain. Remote framing/custody remains the existing
  bounded transport. Socket timeouts do not imply cancellation or non-execution.

## ForgeAI boundary

The separate provider session constructs only a chat host (four execution slots,
chat grant and, remotely, Secret-use grant). It never constructs CodingAgent,
mutation, Git, shell, Docker, tunnels or an alternate provider. A literal loopback
IP is required for local no-auth mode; remote mode requires HTTPS, interactive
Secret provisioning, operator disclosure policy and an existing custody directory.
No ambient proxy or credential configuration is used.

Three fixed synthetic contracts run once, stopping on the first failure: READY,
one exact JSON object, and an AST-equivalent Python addition function. Code is
parsed, never executed. Native structured output is not enabled or claimed.
The exact configured model must be echoed by the existing adapter contract.

Only a successful session can attempt one summary of one explicit file. The
operator approves its repository, target and endpoint separately. Remote policy
must independently admit the repository classes; a synthetic-only policy never
does. The local adapter rejects link/reparse traversal and reads at most 16 KiB.
No directory listing, recursive expansion, mutation capability or automatic retry
exists in this path. It assumes a trusted, stable local filesystem namespace,
as the existing workspace contract specifies. Source secrets are not detected:
the operator must approve only suitable source content.

## Qualification limits

Synthetic success establishes interoperability for this session, not model quality,
deployment availability or production readiness. Read-only output is untrusted
text, never instructions for effects. No model output is evaluated or executed.
Bounded response hashes and check names are returned; response text is not added
to durable evidence. Existing remote custody remains authoritative about sends.
Kaggle runtime evidence is infrastructure evidence only; a separately available
endpoint is required. There is no always-on notebook service assumption.
