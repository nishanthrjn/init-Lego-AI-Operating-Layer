# ADR-019 — Configuration-selected Model contributions

Status: Proposed; narrow implementation authorized by the maintainer's
configuration-driven composition instruction. No broader production qualification.

Cross-reference (2026-09-28): accepted [ADR-014](ADR-014.md) §3.5 extends use of
the same pinned selected binding to the existing v1 embedding capability, for the
public local-host facade only. There is no second selection mechanism; this
record's capture, pinning and failure rules are unchanged.

## Decision and evidence

The assessment starter's local provider branches and dotenv loading demonstrated
a composition gap. Keep canonical contracts and the existing Catalog, resolver,
Plugin lifecycle and governed Model invocation. Add only private runtime wiring
in model_selection.py, not a generic ProviderRegistry or a new owner.

Application CapabilityRequirement -> captured desired configuration binding ->
admitted contributions published in Catalog -> existing capability resolver ->
exact provider/Plugin lifecycle/configuration association -> ModelPort ->
existing governed invocation.

The operator supplies immutable ModelContribution associations. Each retains
the ModelBinding, full CatalogEntry, exact ConfigurationRevisionRef and existing
PluginLifecycleRecord (admission plus transition revision). Its constructor is
trusted executable host wiring, never a path/name loaded from configuration.
Configuration selects a binding; it does not create an admission, revision,
activation, tenant, grant or implementation. The full compatible candidate set
is retained; the explicitly configured binding selects among it.

Application Composition retains configuration ownership. Plugin Lifecycle
retains admission/activation ownership, Catalog owns publication, and Execution
and Governance retain invocation authority. The composition module may read
Plugin lifecycle contracts, without moving them into Model contracts.

## Scope and alternatives

Use a closed two-field captured mapping and explicit owner-supplied revision.
No configuration database/service, file format framework, discovery, arbitrary
imports, mutable global registry, default provider, fallback or retry.
A generic configuration language or registry would duplicate owners and expand
trust; app-local provider branches fail reuse. This private bounded slice
does not yet promise a stable public application-authoring API.

Only v1 Chat is executable here. Capability/version resolution is necessary but
not proof of behavioral equivalence. ModelPort chat/embed and provider features
remain unchanged. Future negotiated constraints/extensions must preserve their
meaning; broad Port shape alone is never sufficient compatibility evidence.

## Operational boundaries

Factories must be bounded, local, no-I/O construction under trusted host control.
They capture settings pinned to the supplied configuration revision. This slice
does not supervise arbitrary initialization, acquire resources, or shut down
long-lived clients. ImportError and construction errors are explicit failures;
causes remain restricted diagnostics. No configuration value executes code.

Existing Lifecycle records are not a durable activation store. The host must
supply current activation records and manage Catalog withdrawal on disablement.
Dispatch still checks Catalog/current authority. Existing dispatch-to-invocation
race and in-process trust limitations remain; there is no atomic live reload.
Changing settings requires a new owner revision and appropriate reactivation,
never mutation of an existing contribution.

Fresh-process reconstruction requires the same owner-supplied exact configuration
and newly supplied valid lifecycle/catalog state. It does not resurrect historical
authority, resume in-flight work or persist activation state.

## Verification and deferred qualification

See [proof and acceptance matrix](../docs/model-composition.md).
The same offline classification consumer runs FixedModel and OllamaModelAdapter
with mocked HTTP, selected by different valid bindings. This proves assembly and
a deterministic application contract, not live quality/cost/latency equivalence.
Secret references are not needed by these credential-free fixtures. Secret fields
are rejected rather than inventing a raw-secret path; authenticated providers
require governed Secret integration before support.

Preserve ADR-002/003/006/015/016, PLG-025–027/038, SEC-057–059 and existing governed
Model failure/effect semantics. No new canonical entity or provider contract.
