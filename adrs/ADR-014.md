# ADR-014 — Public local governed host composition boundary

**Status:** Accepted — 2026-09-28, by explicit maintainer decision after review
(CR-1a closed). §13 records the resolved decisions. Acceptance authorizes CR-1b
to implement this boundary; it does not itself implement anything or constitute
conformance evidence.
**Allocated:** 2026-09-28 by explicit maintainer instruction (CR-1a).
**Decision owner:** Architecture / reference-runtime maintainer.
**Depends on:** ADR-002 (package boundaries), ADR-003 (revision binding), ADR-005
(authority/tenant), ADR-007 (dispatch), ADR-008 (effects), ADR-015 (supervision),
ADR-017 (Agent), ADR-019 (configuration-selected Model contributions).
**Effect of acceptance:** narrowly supplements ADR-002 §12 by naming one public
composition module, and extends use of ADR-019's pinned selected binding to the v1
embedding capability for this facade only (§3.5). No canonical semantics, owner or
effect meaning changes.
**Scope note:** readiness planning reserved this number for "Reference Application
Authoring and Composition Experience". This record decides only the public
*local governed host* boundary that current consumers prove necessary. Manifests,
workflow authoring and supported third-party Plugin authoring remain undecided.

## 1. Decision question

How can an application obtain supported governed LegoAI capabilities through a
public, versioned entry point without importing `legoai.reference.*` or
`legoai.runtime._composition.*`, while preserving configuration revision binding,
capability resolution, current authorization, execution/effect semantics and
replaceable adapters?

## 2. Current problem (verified at `09f6dd1`)

**Boundary rules.** ADR-002 §11 makes every `legoai.reference.*`, `_composition`
and private helper name internal. The public surface is Kernel, owner
`values`/`ports`, Plugin SPI and a thin `legoai.runtime.api`. ADR-002 §12 reserves
`runtime.api` as a contract-only facade and defers "actual factories, instance
lifetime, bootstrap order, config loading and authorization". Today
`legoai/runtime/__init__.py` is inert and **no `runtime.api` exists**.
IMPLEMENTATION-READINESS §4 adds that ADR-002 "does not authorize a public alias
for private wiring". Gate 3 (items 2 and 4) requires a supported entry and
forbids consumers importing private wiring.

**Three independent consumers duplicate the same local governed-host wiring:**

| Consumer | Location | Internal imports | Self-issued authority |
|---|---|---|---|
| DocuMind (v0.1 app) | `examples/documind/src/documind_app/composition.py` | `reference.catalog/evidence/execution/governance/model/plugins/resolution`; `runtime._composition.model_governed` | `Grant` built per invocation (1 h window) |
| Generative media (shipped package) | `packages/legoai-generative-media/.../local_host.py`, `composition.py` | `reference.catalog/evidence/execution/governance/plugins/resolution` | `Grant` built in `prepare_local` |
| Engineering Agents (examples) | `packages/legoai-engineering/examples/governed_demo.py` (+ `repository_analyst.py`, `bounded_coding.py`) | `reference.*`; `_composition.agent`, `_composition.model_governed` | `Grant` built in the demo |

Each rebuilds the in-memory Catalog, Plugin admission and activation, the
authorization evaluator, the dispatch arbiter, the security-context registry and
the Coordinator. The need is proven without ForgeAI, which would otherwise be the
fourth copy.

**Verified behavior the decision must respect:**

- `DeterministicAuthorizationEvaluator.evaluate(SecurityContext)` trusts the `Grant`
  embedded in the context. It checks coverage, revocation, policy currency and
  approval. `InMemoryGrantRegistry` records only revocations. *Whoever builds a
  `SecurityContext` chooses its authority.* That is why consumers must stop
  building them.
- `StaticSecurityContextRegistry.register` keeps one entry per reference, silently
  overwrites an existing key, and has no removal.
- `ExecutionCoordinator` keeps `_states` and `_claimed` per `ExecutionId`, with no
  removal. `_claimed` is the invoke-once guard. It holds an `asyncio.Lock`, so it is
  confined to one event loop.
- `DeterministicDispatchArbiter` serializes arbitration under a `threading.Lock`,
  and denial precedes invocation. On the Model path it only reads evidence custody.
- ADR-019 `capture_model_selection` accepts exactly `{"revision","binding"}` against
  an owner-supplied pinned revision. `compose_model` supports only the v1 Chat offer
  and calls the trusted constructor exactly once.
- `invoke_governed_chat`/`invoke_routed_chat`/`invoke_governed_embedding` map
  failures to NONE (preflight/rejected) or UNKNOWN (uncertain), claim invocation once
  and never retry.
- Capability identities are provider-neutral: `legoai.intelligence.model.chat` and
  `.embedding`, v1.0.0. The only helpers that construct them are Ollama-named
  internals in `reference.model`.
- `OllamaModelAdapter.__init__` stores configuration only; I/O happens in `chat`/`embed`.
- `AgentRuntimePort.run(AgentDefinition, AgentRequest)` requires `AgentRequest.context:
  ExecutionContext`. `AuthorizationPort.evaluate(SecurityContext) ->
  AuthorizationDecision` is public.

## 3. Decision

Adopt a **thin direct-Python public composition facade** (alternative E). An
application opens a single-operator **local governed host** from validated
operator configuration and receives only public contracts. The host composes the
existing reference owners, ADR-019 selection, the M7 Agent runtime and the existing
governed invocation helpers internally. It adds no semantic owner and changes no
authorization, dispatch or effect behavior.

### 3.1 Module boundary

| Module | Public? | May import | Holds |
|---|---|---|---|
| `legoai.runtime.api` | yes | Kernel; owner `values`/`ports`; `execution.agent.ports`; `intelligence.model` contracts; `plugins.values` | Types, `GovernedHost` Protocol, errors. **No factory**, keeping ADR-002's contract-only rule |
| `legoai.runtime.local` | yes | `runtime.api`, `runtime._composition.*`, the selected `legoai.reference.*` realizations | `open_local_host` and the closed built-in provider set. **The only public module allowed to depend on internals** |
| `legoai.runtime._composition.*`, `legoai.reference.*` | no | unchanged | The host's implementation; never re-exported or aliased |

**Applications may import:** `legoai.runtime.api`, `legoai.runtime.local` (in their
composition root only), and public owner `values`/`ports`.
**Applications must not import:** `legoai.reference.*`, `legoai.runtime._composition.*`,
Plugin bootstrap helpers, the Coordinator implementation, in-memory registries, or
provider SDKs. No public signature names an internal type.

### 3.2 Public surface

```python
# legoai/runtime/api.py — public contract types only
class HostFailure(Enum):
    # open-time (ADR-019 vocabulary reused where it exists)
    INVALID_CONFIGURATION = "invalid_configuration"
    STALE_CONFIGURATION = "stale_configuration"
    UNKNOWN_BINDING = "unknown_binding"
    CONTRIBUTION_CONFLICT = "contribution_conflict"
    UNAVAILABLE_PROVIDER = "unavailable_provider"
    INCOMPATIBLE_PROVIDER = "incompatible_provider"
    INVALID_GRANT = "invalid_grant"
    UNSUPPORTED_COMPOSITION = "unsupported_composition"
    MISSING_DEPENDENCY = "missing_dependency"
    INITIALIZATION_FAILURE = "initialization_failure"
    # use-time, raised before any dispatch or provider work
    GRANT_NOT_CONFIGURED = "grant_not_configured"
    SUBJECT_OUT_OF_SCOPE = "subject_out_of_scope"
    PURPOSE_UNAVAILABLE = "purpose_unavailable"
    FOREIGN_CONTEXT = "foreign_context"
    CAPACITY_EXHAUSTED = "capacity_exhausted"
    WRONG_EVENT_LOOP = "wrong_event_loop"

class HostError(Exception):
    failure: HostFailure        # str(error) == failure.value; causes chained as restricted diagnostics

class ModelPurpose(Enum):
    CHAT = "chat"
    EMBEDDING = "embedding"

@dataclass(frozen=True, slots=True)
class OperatorGrant:           # authority as operator data, never application logic
    grant_id: GrantId
    action: str                # e.g. "invoke-capability", "read-for-model-analysis"
    resource_scope: str        # e.g. "legoai.intelligence.model.chat"
    not_before: datetime       # timezone-aware
    expires_at: datetime       # timezone-aware, > not_before

@dataclass(frozen=True, slots=True)
class OllamaSettings:          # closed built-in provider settings (mirrors existing OllamaModelConfig)
    base_url: str
    chat_model: str
    embedding_model: str
    timeout_seconds: float

@dataclass(frozen=True, slots=True)
class ModelBindingConfig:      # one selectable candidate
    binding_id: str
    requirement: ModelRequirement   # logical profile, e.g. "engineering-reasoning"
    provider: OllamaSettings | TrustedModelContribution

@dataclass(frozen=True, slots=True)
class TrustedModelContribution:     # code, never data
    plugin_id: PluginId
    provider_id: ProviderId
    model_id: ModelId
    purposes: frozenset[ModelPurpose]
    construct: Callable[[], ModelPort] = field(repr=False, compare=False)

@dataclass(frozen=True, slots=True)
class LocalHostConfig:
    configuration: ConfigurationRevisionRef   # pinned revision; sole source of tenant + application
    principal: PrincipalRef
    policy: PolicyRef
    grants: tuple[OperatorGrant, ...]         # 1..64; unique ids; unique (action, resource_scope)
    bindings: tuple[ModelBindingConfig, ...]  # 1..16; unique binding_id
    max_executions: int                       # 1..100_000; exact int

@dataclass(frozen=True, slots=True)
class GovernedChatResult:
    execution: ExecutionResult
    response: ChatResult | None = field(repr=False)        # present iff SUCCEEDED

@dataclass(frozen=True, slots=True)
class GovernedEmbeddingResult:
    execution: ExecutionResult
    response: EmbeddingResult | None = field(repr=False)   # present iff SUCCEEDED

class GovernedHost(Protocol):
    @property
    def authorization(self) -> AuthorizationPort: ...
    def model_execution(
        self, purpose: ModelPurpose, *,
        deadline: datetime | None = None,
        correlation: CorrelationId | None = None,
        causation: OperationRef | None = None,
    ) -> ExecutionContext: ...
    def security_context(
        self, subject: ConfigurationRef, action: str, resource_scope: str
    ) -> SecurityContext: ...
    def agent_runtime(self) -> AgentRuntimePort: ...
    async def governed_chat(self, context: ExecutionContext, request: ChatRequest) -> GovernedChatResult: ...
    async def governed_embed(self, context: ExecutionContext, request: EmbeddingRequest) -> GovernedEmbeddingResult: ...

# legoai/runtime/local.py — the single public composition entry
def open_local_host(
    config: LocalHostConfig,
    model_selection: Mapping[str, object],    # ADR-019 closed {"revision", "binding"}
    *,
    clock: Callable[[], datetime] = _utc_now,
) -> GovernedHost: ...
```

`OllamaSettings` and `TrustedModelContribution` appear only in operator
configuration consumed by the application's composition root. Domain code
receives `GovernedHost` and owner Ports only. The provider set is closed: Ollama
is the only built-in. Any other provider needs a new adapter, either added to
LegoAI's built-in set or supplied by the application as a
`TrustedModelContribution`. Configuration alone never adds one.

### 3.3 Evaluation of candidate host members

| Candidate | Decision | Consumer evidence |
|---|---|---|
| `new_execution(...)` | **Narrowed to `model_execution(purpose, …)`** | Every current Coordinator-dispatched execution is a Model invocation (DocuMind, Agents). Engineering reads evaluate authorization directly and dispatch nothing. A generic minting API has no consumer |
| `agent_runtime(binding_selection)` | **`agent_runtime()` without an argument** | Selection is pinned once at open. Per-call selection has no consumer and would let runtime data switch providers inside one pinned host |
| `governed_chat` / `governed_embed` | **Keep** (names match DocuMind's existing methods) | DocuMind |
| `authorization` | **Keep** | Engineering authorized readers (`AuthorizedRepositoryEvidence`) |
| `security_context(...)` | **Keep**, restricted to configured grants | Engineering readers take a `SecurityContext` from trusted wiring |
| Generic capability invocation (generative media `Contribution` path) | **Defer to CR-1c** | Not needed by ForgeAI-1; can be an additive member |
| Revocation/policy mutation, close/shutdown, observation sinks, tenant accessor | **Excluded** | No current consumer; no background resource |

### 3.4 Member semantics

- **`open_local_host`** (synchronous; no provider call):
  1. Validate `config`.
  2. Capture `model_selection` under ADR-019 rules against `config.configuration`.
  3. For each binding, build a `PluginDeclaration` whose offers are the v1 chat and/or
     embedding offers for its purposes. Built-in Ollama declares both; trusted
     contributions declare only what `purposes` lists.
  4. Inspect, validate, admit, initialize and activate it with the existing lifecycle
     helpers, then publish it to a host-private Catalog.
  5. Resolve and compose **only the selected binding** under ADR-019 rules, calling its
     constructor exactly once.
  6. Build the router, Coordinator and Agent runtime.

  Any failure raises `HostError`, and no partially usable host is returned.
- **`model_execution`** mints UUID4 `ExecutionId`/`OperationId` and a unique
  `SecurityContextRef`. It builds the `SecurityContext` **only** from the configured
  grant `("invoke-capability", <purpose capability id>)`, registers it, and returns an
  `ExecutionContext` whose subject is `config.configuration.configuration`.
  - No such grant → `GRANT_NOT_CONFIGURED`, and nothing is registered.
  - The selected binding lacks the purpose → `PURPOSE_UNAVAILABLE`.
  - More than `max_executions` calls → `CAPACITY_EXHAUSTED`.
- **`security_context(subject, action, resource_scope)`** returns a context built from
  the configured grant with that exact `(action, resource_scope)`, if `subject` lies in
  the host's `ApplicationRef`. Otherwise it raises `GRANT_NOT_CONFIGURED` or
  `SUBJECT_OUT_OF_SCOPE`. It registers nothing and does not count toward capacity.
  Consumers pass it to trusted wrappers that call `authorization.evaluate` per effect.
- **`agent_runtime`** returns the M7 `AgentRuntimePort` bound to the selected pinned
  route. `AgentRequest.context` must come from `model_execution(CHAT)`.
- **`governed_chat` / `governed_embed`** refuse a context not minted by this host for
  that purpose (`FOREIGN_CONTEXT`), then coordinate and call the existing routed chat
  or governed embedding helper unchanged.

### 3.5 Model purposes and the ADR-019 relationship

- `ModelPurpose` is a **closed set of the two currently proven purposes**: `CHAT`
  (Agents, DocuMind) and `EMBEDDING` (DocuMind). It is not a purpose-extension
  language. Adding a purpose requires a new decision plus contract and adapter work.
- A binding exposes only purposes its adapter or contribution actually declares
  and supports. Built-in Ollama declares both; a `TrustedModelContribution` declares
  exactly its `purposes`.
- `model_execution(purpose)` fails closed with `PURPOSE_UNAVAILABLE` when the selected
  binding does not support the purpose.
- `ModelPurpose` is a typed enum passed by composition code. Task, request or model
  data cannot introduce purpose identifiers.
- **Compatibility note:** ADR-019's implemented configuration selection was
  chat-only. ADR-014 extends use of **the same pinned selected binding** to the
  existing provider-neutral v1 embedding capability (`legoai.intelligence.model.embedding`
  1.0.0) for the local-host facade. There is no second selection mechanism for
  embeddings. ADR-019's capture rules, pinning and failure categories are unchanged.

### 3.6 Trusted model contributions are composition-root code

`TrustedModelContribution` is trusted operator **code** in the application's
composition root. It is not configuration or data:
- User, task or model-produced data cannot create one.
- Configuration cannot contain import strings, class names or constructors.
- It supplies a `ModelPort` implementation. Application domain logic never receives it.
- Supporting a provider outside the built-in set still means implementing and
  admitting an adapter behind `ModelPort`; editing configuration is not enough.

It is a bounded contribution contract, not a dependency-injection mechanism.

## 4. Operator authority and configuration

- **Applications stop manufacturing authority.** Grants, principal, policy and tenant
  are supplied as validated operator configuration. The host constructs `Grant` and
  `SecurityContext` values internally from that configuration only.
- **Nothing reachable from task data, repository content, model output or end users can
  create or widen authority.** No `GovernedHost` member accepts a `Grant`,
  `SecurityContext`, `TenantContext`, `PrincipalRef`, `PolicyRef`, declaration,
  constructor or revision. `action`/`resource_scope` only *select* among configured grants.
- **Tenant has one source:** `config.configuration`. There is no second tenant field.
- **Validation at open:**
  - naive or inverted grant windows are rejected (`INVALID_GRANT`);
  - so are empty or oversized action/scope strings;
  - duplicate grant ids or `(action, scope)` pairs → `CONTRIBUTION_CONFLICT`/`INVALID_CONFIGURATION`;
  - duplicate binding ids → `CONTRIBUTION_CONFLICT`;
  - selection data with fields other than `revision`/`binding` → `INVALID_CONFIGURATION`;
  - a revision mismatch → `STALE_CONFIGURATION`.
- **Contributions are code or closed data, never loaded names.** There are no class
  names, import strings, `eval`, dynamic module loading or DI manifests. Configuration
  selects among bindings the operator already supplied.
- **Fail closed:** configured-but-expired, revoked or superseded authority is denied at
  dispatch, with `EffectExtent.NONE` and zero provider calls.
- **Not claimed:** IAM, durable or distributed authority, multi-tenant production
  security, or containment of hostile in-process code. Trusted Python can still
  construct public governance values; that remains ADR-012 scope. This is a *data*
  boundary for a single operator.

## 5. Lifecycle, state and concurrency

- There is no global singleton or mutable global runtime. Each `open_local_host` call
  returns an independent host with its own Catalog, registries, arbiter and
  Coordinator, and two hosts share nothing.
- Opening performs deterministic local composition and admission and makes **no
  provider call**. That claim covers the host's own code and the qualified built-in
  constructor (Ollama stores configuration only). A `TrustedModelContribution`
  constructor is operator code: its inertness is the operator's responsibility, and
  the host documents rather than enforces it.
- **Per-run state belongs to `ExecutionContext`.** Existing reference owners, however,
  retain one security-context entry and one Coordinator state/claim record per minted
  execution, with no release API. Releasing claim records would weaken the invoke-once
  guard. The host therefore enforces the **hard lifetime capacity** `max_executions`.
  In-flight work is unaffected when it is reached, and the operator opens a new host.
  - There is no per-execution release and no silent eviction of execution or
    security-context records. The invoke-once guard is not weakened.
  - Exhaustion fails closed with `CAPACITY_EXHAUSTED`.
  - `max_executions` is a bounded **reference-host lifetime control**, not a measured
    production scalability limit.
  - Memory grows O(`max_executions`), but practical memory capacity has not been
    benchmarked. The permitted maximum (100,000) is a validation ceiling, not an
    operationally validated execution count.
- **Concurrency:**
  - Executions may run concurrently within one event loop.
  - The host is confined to the thread that opened it and to the event loop of its
    first async call. Other loops or threads fail with `WRONG_EVENT_LOOP` before any effect.
    This follows from the reference Coordinator's `asyncio.Lock`. It is a
    reference-host operational limitation, not a domain contract, and no cross-loop
    synchronization is introduced.
  - There is no admission limit, queue or worker pool.
- **No shutdown API:** the host owns no background task, thread or long-lived client.
- A configuration change means opening a new host; there is no live reload. ADR-015
  supervision is not reopened.

## 6. Failure and effect semantics

- **Open-time:** closed `HostFailure` categories. The ADR-019 `CompositionFailure`
  categories map one-to-one where they exist. Constructor `ImportError` →
  `MISSING_DEPENDENCY`; other constructor errors → `INITIALIZATION_FAILURE`.
- **Use-time `HostError`s** are raised before registration, dispatch or provider work.
- **Invocation keeps existing semantics:**
  - Coordinator denial or rejection → no provider call, effect NONE;
  - preflight/rejected provider errors → NONE;
  - uncertain → **UNKNOWN**, never collapsed to NONE;
  - one invocation claim; no retries, no fallback.
- Deadlines keep the existing Coordinator semantics for `ExecutionContext.deadline`
  plus each adapter's own timeout. Cancellation propagates, and claims are not replayed.
  No new deadline, cancellation or provider-cessation guarantee is made.

## 7. Alternatives

| Option | Assessment |
|---|---|
| **A.** Keep private composition; document exceptions | Rejected: permanent private coupling, three copies becoming four, Gate 3 unmet, consumers keep self-issuing grants |
| **B.** Make `legoai.reference.*` public | Rejected: freezes realizations; contradicts ADR-002 §11; exposes in-memory owners and Coordinator internals |
| **C.** Builder / fluent API | Rejected: adds an abstraction layer with no evidence of simpler authoring; the same validation fits one function |
| **D.** Declarative manifest / generic DI container | Rejected: new representation and loader surface; constructors still need code; ADR-002 excludes DI/service locators; invites import strings |
| **E.** Thin direct-Python facade (types in `runtime.api`, one entry in `runtime.local`) | **Selected.** Matches ADR-002 §12, readiness §4's "direct Python API" candidate, and generative media's proven `open_*(config)` + closed driver-set pattern |
| Variant: put the factory in `runtime.api` | Rejected: breaks ADR-002's contract-only `runtime.api` rule |
| Variant: fresh reference owners per execution | Deferred: bounds state trivially but re-admits per run and splits the invoke-once guard; revisit only with evidence |

**Additional required tests:**

- **Inert open.** For built-in Ollama and a trusted fake:
  - a socket/urllib guard records zero network attempts;
  - no new tasks, threads or files appear;
  - the constructor is called once, at open.
- **Constructor failures.** Constructor `ImportError` and other errors map to their
  categories, and no host is returned.
- **Negative configuration.** Selection data carrying `tenant`, `grant`, `class`,
  `import` or `secret_ref` is rejected.
- **Grant validation.** Duplicate or invalid grants are rejected.
- **Scope.** `security_context` refuses a subject outside the host's application.
- **Capacity.** At the `max_executions` boundary, call N succeeds and call N+1 raises
  `CAPACITY_EXHAUSTED`.
- **Loop confinement.** Use from another loop or thread raises `WRONG_EVENT_LOOP`.

Qualification is offline and deterministic. A live DocuMind Ollama smoke run is
recommended for parity; it does not qualify other providers.

## 11. Compatibility and replaceability

Distribution `0.1.0.dev0`: only the §3.2 names are supported. Before 1.0 they may
change only with a documented migration note, and never with a silent change of
meaning. Applications depend on the `GovernedHost` Protocol and owner Ports. A
future durable, remote or multi-tenant host, which would be a separate decision,
can implement the same Protocol without application domain changes. The local
realization remains replaceable behind `open_local_host`.

## 12. Out of scope

DI container, service locator, Plugin container, workflow language, generic
application builder, manifest format, remote hosts, durable IAM, multi-tenant
hosting, Secret resolution (ADR-010; the built-in Ollama provider is credential-free),
supervision/shutdown (ADR-015), observation integration (ADR-013), engineering
capabilities (CR-2/CR-3) and generative-media migration (CR-1c).

- **Pre-existing M8.3 test defect:** a test expected `ValueError` where CPython
  3.13+ `dataclasses.replace` raises `TypeError`.

No live provider, Docker or network was used; no live-provider qualification is
claimed.

Clarifications made during implementation, all within this decision:

- **Selected binding only.** Only the selected binding is admitted, published to
  the host-private Catalog and constructed. Unselected bindings are validated as
  configuration but never admitted or constructed. This narrows §3.4 step 3–4.
- **Current authorization at dispatch.** The host-private
  `SecurityContextResolutionPort` re-stamps `established_at` with the host clock
  when the Coordinator resolves a context. A grant that expires between
  `model_execution` and dispatch is therefore denied, matching the engineering
  authorized readers. Registration never overwrites an existing reference.
- **Built-in provider identity.** `OllamaSettings` also carries the operator
  `provider_id`. The existing routed Chat check compares response identity with
  the pinned binding.
- **Operator convenience.** `ModelPurpose.capability_id` exposes the v1
  capability identity each closed purpose maps to, so operators can write
  `OperatorGrant.resource_scope` without importing reference helpers.
- **Embedding path.** A private `invoke_routed_embedding` (pinned entry, same
  subject/tenant checks as routed Chat) shares the existing embedding effect
  mapping with `invoke_governed_embedding`. The legacy path is unchanged.
- **Confinement.** `legoai.reference.execution` gains `running_event_loop()` and
  `current_thread_ident()`, because `legoai.runtime` may not import `asyncio` or
  `threading`. No Coordinator change, lock or thread was added.
- **Remaining listed exceptions.** Generative media's `local_host.py` and
  `composition.py` (CR-1c). Core's own top-level technical examples
  (`examples/agent.py`, `model_routing.py`, `model_port.py`) remain internal
  demonstrations.

## 13. Maintainer decisions (resolved 2026-09-28)

1. **Placement — Accepted.** `legoai.runtime.local` is the **one** public composition
   module that may depend on `legoai.runtime._composition.*` and the selected
   `legoai.reference.*` realizations. This narrowly supplements ADR-002 §12, and the
   exception extends to no other public module. `legoai.runtime.api` stays
   contract-only.
2. **Embedding scope — Accepted, with narrow clarification.** CHAT and EMBEDDING
   form the closed supported purpose set, per §3.5 and its ADR-019 compatibility note.
   DocuMind is the existing consumer evidence for embedding. Excluding it would have
   kept a private composition path alive.
3. **State bound — Accepted.** `max_executions` is the hard lifetime capacity, per §5,
   with no release, no eviction and fail-closed exhaustion. CR-1b must test
   deterministic capacity enforcement.

All other boundaries in this record are accepted as written:
- thin direct-Python facade;
- no builder, service locator, DI container, manifest language, application framework
  or global singleton;
- no provider I/O at open;
- operator-configured authority, with no self-issued grants;
- no import strings, class names or `eval` from configuration;
- replaceable adapters;
- no generic capability invocation;
- generative-media migration in CR-1c;
- no supervision redesign;
- unchanged NONE/COMPLETED/UNKNOWN effect semantics;
- no facade retries.
