# ADR-018 — Repository Analyst composition in Engineering

Status: Proposed; implemented under the maintainer's scoped M8.1 instruction.
Local validation pending. Depends on ADR-002, ADR-017 and M6.5.

## Decision

Place the repository-specific request, bounded evidence, analysis values and
composition in `legoai_engineering.analyst`. An optional `analyst` extra depends
on the existing `legoai-reference` distribution. The base Engineering install
keeps zero runtime dependencies. Core does not import Engineering. There is no
new distribution, third-party runtime dependency or change to generic Agent or
Model contracts.

Use two deterministic phases. Trusted composition authorizes selected reads and
model disclosure against an explicit M2 workspace and exact path allowlist.
It obtains complete bounded files through RepositoryWorkspacePort. The Analyst
then calls the existing M7 runtime once using `engineering-reasoning`, and validates
a closed JSON analysis schema plus exact evidence-member path references.

The private read composition uses existing Governance evaluation before each
read and before releasing the bundle. It requires a `read-for-model-analysis`
scope and rejects approval-bearing contexts. This is a trusted local read/disclosure
boundary, not a new catalog capability or security boundary against hostile Python.
The operator owns workspace identity, principal, permission and model-destination
association. Separate existing governed Chat authorization remains mandatory.

## Alternatives and consequences

A Core specialization would reverse package ownership. A new distribution adds
release overhead without an independent consumer requirement. Putting all behavior
in an example would not provide a reusable typed specialization. A tool loop adds
authority and termination problems that this explicit-file use case does not need.

M2 stable-workspace assumptions and synchronous I/O limitations remain. Evidence
is not an atomic snapshot or canonical Evidence. Only structured citation membership
is validated; narrative and any paths mentioned inside narrative remain unverified.
Accepted-output limits do not bound provider generation, transport or cost.
No write, Git, execution, memory, retry, fallback, Workflow or Team surface is added.

Qualification requires the affected Engineering suite, Core Agent/Model/routing
regressions, import/dependency checks and fresh wheel installation with and without
Core. No runnable validation was performed internally; see the Engineering README.
