# ADR-017 — bounded one-step Agent composition

Status: Proposed; implemented for local M7 qualification under the maintainer's
explicit scoped instruction. Does not amend canonical semantics or grant wider
runtime qualification. Depends on ADR-002, ADR-015, ADR-016 and M6.5.

## Decision

Place Agent contracts under `legoai.execution.agent`, as ADR-002 specifies.
Introduce an execution-owner AgentId (no canonical implementation already exists),
distinct from ExecutionId and PrincipalId. Definition identity plus behavior
version describes reusable behavior, not an operational instance or authority.

Implement one stateless step through an injected ModelRouterPort and an
Agent-owned governed Chat Port. Its private composition realization uses the
existing Coordinator and invoke_routed_chat. Agent reference code cannot import
peer reference implementations or invoke ModelPort. The extra Port preserves
ownership and provides a typed external-enforcement boundary; it is trusted
composition, not protection against hostile Python implementations.

Choose bounded nonblank UTF-8 text rather than JSON/schema machinery. Instructions
and input have byte limits; deterministic prompt content has a total byte budget.
Validate returned model text before constructing success, retaining the exact
downstream ExecutionResult even when output is unacceptable. Do not truncate or
rewrite completed/unknown model effects. No private reasoning is recorded.

Accepted-output limits do not bound provider generation, tokens, transport memory
or provider cost. Existing Model contracts and adapters remain unchanged.

## Alternatives and consequences

- Direct ModelPort calls would bypass the qualified governed boundary: rejected.
- Importing private composition from reference Agent code reverses dependencies:
  rejected. Composition implements the Agent-owned Port instead.
- An Agent framework, instance supervisor, loop or schema dependency adds scope
  without a present consumer: deferred. Exactly one step is supported; there is
  no configurable step count or operational-instance lifecycle claim.

Caller-supplied ExecutionContext retains tenant, security reference, correlation
and deadline semantics. Cancellation/unexpected faults propagate; existing
Coordinator/adapter cancellation, currentness and in-process replay limitations
remain. A retry requires explicit new execution identity, never an Agent loop.
No public authoring facade, production Agent Plugin lifecycle, tools, memory,
Workflow or Team is qualified. No automatic Artifact/Evidence/usage accounting.

Validation: contract, real governed fake-model integration, bypass/import controls,
existing Model/routing regressions, Core packaging and offline example. All local
execution evidence remains pending. No canonical document is changed.

## Addendum (2026-10-08): ADR-022

[ADR-022](ADR-022.md) (Proposed) lets a caller of Model chat request a
provider-enforced structured reply. The generic Agent boundary defined here
is unchanged: Agent output is still bounded, validated text, and
`AgentDefinition` gains no schema field.
