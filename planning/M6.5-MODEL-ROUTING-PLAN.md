# M6.5 — model routing foundation

Status: implementation complete; local validation pending. M1–M6 retain
their qualified scopes. M7 is unstarted.

Problem: ModelPort invokes an already configured adapter; it cannot express a
future consumer's provider-independent logical model requirement. Add Chat-only
exact profile matching under Model Interaction (ADR-002), separate from Execution.

Public additions: ModelBinding, ModelRequirement, ModelRouteStatus,
ModelRouteDecision and ModelRouterPort. DeterministicModelRouter is a pure
reference implementation. The routing Port lets consumers depend on the selection
contract without importing its realization; ModelPort remains unchanged.

Bindings contain only a binding ID, logical profile, existing ModelId and
ProviderId. An explicit ConfigurationRevisionRef identifies the operator-supplied
immutable configuration. Duplicate binding IDs are invalid. Zero, one or multiple
exact profile matches produce NO_MATCH, RESOLVED or AMBIGUOUS. Candidate order is
configuration order, never preference. TenantContext must match the revision scope.

Decisions retain the exact revision and complete matching bindings. Private
composition associates one revision/binding with an exact CatalogEntry and a
trusted configured ModelPort. It rejects a changed revision, binding, tenant,
configuration subject or catalog entry before invocation. That association retains
the adapter reference; no mutable registry is consulted. The operator must not
reconfigure that adapter in place or reuse a revision for changed configuration.
Returned model/provider identities are checked against the selected binding.
This is trusted local composition, not attestation of an arbitrary adapter or
of immutable weights behind a provider's mutable model alias.

Capability resolution still chooses a published capability; current authorization,
dispatch and ExecutionCoordinator still govern the call. Routed Chat reuses the
existing invocation claim, phase-error mapping and settlement implementation.
The existing v1 chat capability is retained, independently of provider identity.
Future admitted adapters use ModelPort plus explicit operator composition; no
provider is implemented here. The normalization-specific ConfigurationStorePort
is not widened and no second configuration store is created.

Non-scope: retries, fallback, ranking, discovery, health, credentials, SDKs,
embedding routing, Agents, Workflows, Teams, evidence creation, new dependencies,
new distributions, sandbox changes or expanded runtime guarantees. No ADR or
canonical document changes are needed. M7 waits for M6.5 local qualification.

Verification: focused routing/invariant/architecture and governed integration
tests, existing Model regressions, Core suite, typing, Ruff, wheel/fresh install
and a deterministic offline example. Shared chat composition requires DocuMind's
relevant regression. All execution is reserved for the maintainer; implementation
receives static source review only.
